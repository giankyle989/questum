## 4. Description

**Apple limit:** 4,000 characters.

Three drafts at increasing length so you can pick a verbosity that matches your launch voice. Every draft follows the same beat order: pitch → how it works → six attributes → missions/streak → honest decay mention → privacy story → device requirements → closing CTA.

The word `AI` is deliberately avoided in description bodies (it appears only in the privacy nutrition rationale and in the keywords field). This minimizes the chance Apple's reviewers treat Questum as an "AI app" subject to whichever AI-specific questionnaire is current at submission time.

### 4A. Short draft (~1,200 chars)

> Questum is a character-progression tracker for your real life.
>
> Type what you did today. Questum turns it into XP across six attributes. Watch your character grow. That's the whole loop — no checklists, no tagging, no upfront goal-setting.
>
> The six attributes mirror the classic role-playing template, mapped to real-life domains:
>
> • STR — physical exertion, lifting, sports, manual work
> • DEX — cooking, music, crafts, fine motor practice
> • CON — sleep, hydration, cardio, healthy meals
> • INT — reading, studying, courses, deep learning
> • WIS — meditation, journaling, reflection, planning
> • CHA — calls, hangouts, presentations, creative work
>
> Each morning Questum picks three daily missions weighted toward your weakest attributes. Stay consistent and your streak builds a small XP multiplier. Skip a few days and your in-progress XP slowly fades — your levels never decrease, only the bar to your next one.
>
> Questum runs entirely on your iPhone. Logs are parsed by your phone's on-device intelligence — they never leave the device. No accounts. No cloud. No subscriptions. No ads.
>
> Requires iPhone 15 Pro or newer. One-time purchase.
>
> Level up the parts of yourself that actually matter.

## 5. Keywords

**Apple limit:** 100 characters total, including commas, single-byte commas, no spaces. Apple deduplicates words already in App Name and Subtitle.

**Forbidden (already auto-indexed from §1 + §2):** questum, level, up, real, life, rpg, stats, for.

**Proposed:**

```
habit,tracker,productivity,journal,AI,character,XP,gamify,attributes,streak,growth,leveling,skills
```

Character count: 98.

Rationale per keyword group:

- **Genre / category:** `habit`, `tracker`, `productivity`, `journal` — captures the closest competitor search buckets (Habitify, Streaks, Habitica, Daylio).
- **Mechanic:** `XP`, `gamify`, `attributes`, `streak`, `leveling`, `skills` — captures users looking specifically for gamified or RPG-style trackers.
- **Audience pull:** `growth`, `character` — captures self-improvement intent without leaning on "self-improvement" itself (16 chars; budget-prohibitive).
- **Differentiator:** `AI` — the only place "AI" lives outside the privacy paragraph. Lets users searching for AI tools find Questum without the description body inviting Apple's AI-app questionnaire.

## 8. Privacy Nutrition Label

Every section in App Store Connect's Privacy Nutrition flow should be marked **Data Not Collected**. One-line rationale per section:

| Apple section | Selection | Rationale |
|---|---|---|
| Contact Info | Data Not Collected | No accounts, no sign-up, no email capture in MVP. |
| Health & Fitness | Data Not Collected | Log text stays on-device; no HealthKit reads or writes in MVP. |

| Location | Data Not Collected | No location permissions requested or used. |
| Sensitive Info | Data Not Collected | No religious, political, or biometric data captured. |
| Contacts | Data Not Collected | No address book access. |
| User Content | Data Not Collected | Logs are stored locally in SQLite and never transmitted off-device. |
| Browsing History | Data Not Collected | No web view, no URL tracking. |
| Search History | Data Not Collected | No in-app search telemetry. |
| Identifiers | Data Not Collected | No advertising identifier, no device identifier, no analytics SDK. |
| Purchases | Data Not Collected | App Store handles purchases server-side; we never receive identifiers. |
| Usage Data | Data Not Collected | No analytics, no crash reporting in MVP (revisit post-launch only with explicit privacy update). |
| Diagnostics | Data Not Collected | No crash logs sent to us. Apple-level crash reports stay with Apple if the user opts in at the OS level. |
| Other Data | Data Not Collected | Nothing else collected. |

**Apple Foundation Models / AI note:** the on-device intelligence is part of iOS itself. Questum sends log text to the on-device model and receives structured output back — both happen entirely on the user's iPhone. This is not "data sharing with third parties" in Apple's privacy terminology. The nutrition rows above are accurate.

## 11. Screenshots Plan + Composition

Capture happens in Phase 5 on real iPhone hardware after the EAS production build runs. This section gives the Phase 5 capturer everything they need: device sizes, capture order, per-screen setup, composition spec, and overlay caption strings.

### 11.1 Required device sizes

Apple requires screenshots for the largest display size your app supports. Because Questum gates to iPhone 15 Pro and newer, the gating buyer base spans the 6.1" / 6.7" / 6.9" displays. Submit:

- **6.9" display** (iPhone 17 Pro Max et al.): 1320 × 2868 portrait. **Required.**
- **6.7" display** (iPhone 16 Pro Max, 15 Pro Max): 1290 × 2796 portrait. **Required for older Apple-Intelligence iPhones in the gated list.**

Apple auto-downscales 6.9" screenshots to 6.1" and 5.5" displays if smaller-size screenshots are not provided. Provide the 6.9" and 6.7" sets explicitly to avoid scaler artifacts on the marketing surface.

Three to ten frames are accepted per device size. Submit all six listed below.

### 11.2 Capture order and per-screen setup

Capture in this exact order so the listing tells the loop story top-to-bottom. Each screen has an explicit setup state — recreate it before tapping the screenshot button. Use a fresh build with seeded fixture data; do not use a developer profile with months of real logs.

| # | Screen | Setup state |
|---|---|---|
| 1 | Character Sheet | Character at total Level 4. Attribute states: STR L4 / DEX L3 / CON L5 / INT L4 / WIS L3 / CHA L4. Streak indicator shows 5-day streak. Most-recent-logs strip shows "Ran 5k", "Read 30 pages", "Cooked dinner from scratch". |
| 2 | Log Entry modal | Modal open mid-typing. Field shows half-typed text "Ran 5k this morning before wo" with the cursor visible. Voice-input button unhighlighted. |

If real production data is too sparse at capture time, seed via the same fixtures Phase 3 uses for the mock AI. Do NOT capture with real personal logs — they tend to include private details and produce unflattering attribute distributions.

### 11.3 Composition spec (Treatment A — bold caption on top, full-bleed phone below)

This is the locked treatment. Each frame is a portrait-oriented composition rendered at the device-size resolution from §11.1.

- **Output canvas:** 1290 × 2796 (6.7") or 1320 × 2868 (6.9"). Portrait.
- **Background:** solid `#0E1116`. No gradient, no noise, no decorative pattern — keep it identical to the app background so the device frame doesn't feel pasted on.
- **Caption block:** top of frame, ~16% of vertical height (~447px tall on the 6.7" canvas). Left-aligned. Two-line maximum.
  - Line 1: color `#E6EDF3` (warm off-white), Manrope ExtraBold (weight 800), size ~64pt rendered.
  - Line 2: color `#E8C547` (gold accent), Manrope ExtraBold (weight 800), same size as line 1. Single weight, single size — the color shift is the only emphasis.
  - Horizontal padding: 64pt from the left edge to the start of glyphs.
  - Line height: ~1.1×.
- **Phone area:** ~84% of vertical height. The screenshot is full-bleed inside an iPhone device frame. Use Apple's official Marketing Resources device frame (download from the developer site for the exact iPhone 17 Pro Max / 16 Pro Max model). Acceptable fallback: Mockuuups Studio or similar — verify the frame matches the device's actual bezel/Dynamic Island geometry.
- **Phone-area padding:** ~32pt left/right margin between the device frame's outer edge and the canvas edge. Centered horizontally. The device frame's top edge sits ~24pt below the caption block.
- **No drop shadows, no glow, no parallax tilts.** The treatment reads at App Store thumbnail size because the caption is bold and the phone screenshot is the dominant element.
- **Font availability:** Manrope ships with the app. For screenshot composition, install Manrope locally (the `Manrope_800ExtraBold.ttf` weight) before rendering so the captions match the in-app typography.
